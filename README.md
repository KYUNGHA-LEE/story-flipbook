# 동화책 플립북

그림책·동화책·사진첩 이미지를 올리면 실제 종이책을 넘기는 듯한 3D 효과로 보여주는 웹앱입니다.

- 주소: https://story-flipbook.vercel.app
- 머리글: 왼쪽에 앱 이름, 오른쪽에 "made by 이경하"와 "Claude 수정 · 날짜"를 표시합니다. 날짜는 `src/App.tsx`의 `UPDATED_DATE`이며 앱을 고칠 때마다 그날 날짜로 바꿉니다. (GitHub 저장소에 처음 올린 날은 2026.06.21)
- 이미지는 서버로 보내지 않고 **브라우저 안에서만** 처리합니다. 위 주소(원본 사이트)에는 로그인도 링크 공유도 없습니다.
- 만든 책은 **"JSON으로 저장"** 으로 파일(`플립북_날짜_시간.json`) 하나로 내려받고, **"불러오기"** 로 다시 열 수 있습니다. 이미지가 JSON 안에 base64로 들어 있어 이미지 용량의 약 1.33배 크기의 파일이 만들어집니다.
- **"링크 만들기"**(2026-11-18 추가 — 실제 저장소로 올리는 시험은 아직 못 함): **자기 Vercel 계정에 복사해 만든 사이트에서만** 보이는 버튼입니다. 책을 그 사람의 저장소에 올리고 `…/?b=책번호` 주소를 만듭니다. 주소를 열면 책이 바로 펼쳐집니다. 아래 "링크 공유" 절 참고.
- **내 사이트 만들기 안내**: 주소 뒤에 `?mysite` 를 붙여 열면(https://story-flipbook.vercel.app/?mysite) 교육생용 안내와 [내 사이트 만들기 시작] 버튼이 나옵니다.
- 올린 이미지의 비율(가로형·세로형·정사각형)에 맞춰 책 크기가 자동으로 정해집니다.
- PC에서는 두 페이지를 펼쳐서, 모바일에서는 한 페이지씩 보여줍니다.
- 책장은 마우스 드래그·클릭·스와이프·키보드 방향키로 넘길 수 있습니다.

## 링크 공유

**저장소는 사이트를 올린 사람의 것만 씁니다.** 원본 사이트(이경하 선생님 계정)에는 저장소를 연결하지 않습니다 — 선생님의 Vercel 키·저장소를 교육생이 쓰지 않게 하려는 것입니다(2026-11-18 결정). 링크를 쓰려는 사람은 이 사이트를 자기 Vercel 계정에 복사해 "내 사이트"를 만듭니다.

- **내 사이트 만들기**: `?mysite` 안내 화면(`src/components/MySiteGuide.tsx`)의 [내 사이트 만들기 시작] 버튼은 Vercel 의 복사 배포 주소(`https://vercel.com/new/clone?repository-url=…&stores=[{"type":"blob","access":"public"}]`)입니다. 이 저장소를 그 사람의 GitHub 에 복사하고, 그 과정에서 Blob 저장소(공개)를 그 사람 계정에 만들어 연결합니다. GitHub 계정과 Vercel 계정이 필요합니다. `stores` 값의 형식은 Vercel 문서(https://vercel.com/docs/deploy-button/source)로 확인했고, **실제로 끝까지 눌러 보는 시험은 아직 못 했습니다**(선생님 계정이 아닌 계정이 필요). 안내 화면의 순서도 Vercel 화면을 보고 쓴 것이 아니라 문서를 보고 쓴 것이라, 첫 시험 뒤에 실제 화면에 맞게 고쳐야 합니다.
- **버튼이 보이는 조건**: 화면이 `GET /api/share-config` 에 물어 저장소가 연결되어 있을 때(`{"enabled":true}`)만 [링크 만들기] 버튼을 보입니다. 원본 사이트와 내 컴퓨터의 개발 서버에서는 보이지 않습니다. 이 함수는 키가 있는지 없는지만 답하고 키는 내보내지 않습니다.
- 그 사이트의 주소를 아는 사람은 누구나(로그인 없이) 책을 올려 링크를 만들 수 있고, 링크 주소를 아는 사람은 누구나 그 책을 볼 수 있습니다.
- **저장소**: Vercel Blob(공개 저장소). 프로젝트에 저장소가 연결되면 환경변수 `BLOB_READ_WRITE_TOKEN` 이 생기고, 그때부터 동작합니다. 이 키는 서버 함수 안에서만 쓰고 브라우저로 보내지 않습니다(브라우저에는 책 파일 하나만 올릴 수 있는 10분짜리 허가만 줍니다).
- **올릴 때** (`src/lib/shareBook.ts`): 그림의 긴 변을 1400px 이하 JPEG 으로 줄이고(이미 작은 그림은 그대로), 책 한 권을 **파일 하나**(`books/<책번호>.flipbook`)로 묶어 브라우저에서 저장소로 바로 올립니다.
  파일 하나로 묶는 이유: 무료 한도가 "올리기 횟수"로도 걸려 있어 쪽마다 따로 올리면 금방 찹니다.
- **서버 함수** (`api/`):
  - `POST /api/share-upload` — 책 번호를 받아 그 파일 하나만 올릴 수 있는 10분짜리 허가를 내줍니다. 내주기 전에 보관 기간이 지난 책을 지우고, 저장소가 800MB 를 넘으면 거절합니다.
  - `GET /api/book?id=책번호` — 책 파일의 주소와 보관 기한을 알려 줍니다. 기한이 지났으면 지우고 "지워진 책"이라고 답합니다.
- **정한 값** (`shared/share-config.js`, 화면과 서버가 함께 씀): 보관 30일 · 최대 60쪽 · 책 한 권 20MB · 그림 긴 변 1400px · 저장소 800MB 에서 새 링크 중단.
- **Vercel 무료(Hobby) 한도** (2026-11-18 Vercel 문서 확인): 저장 1GB · 월 전송 10GB · 월 고급 작업 2,000회(책 한 권 = 목록 확인 1 + 올리기 1) · 단순 작업 10,000회. **한도를 넘으면 요금이 나오는 대신 저장소가 30일 동안 막혀 이미 만든 링크도 열리지 않습니다.**
- **알아 둘 점**: 로그인이 없으므로 누군가 일부러 많이 올리면 그 사이트 주인의 한도가 소진될 수 있습니다. 한 사람의 한도가 차도 다른 사람의 사이트에는 영향이 없습니다. 책 번호는 12자리 무작위라 추측으로는 열 수 없지만, 주소를 받은 사람은 다른 사람에게 다시 보낼 수 있습니다.
- 내 컴퓨터의 개발 서버(`npm run dev`)에는 `/api` 가 없어 [링크 만들기] 버튼이 보이지 않고 링크로 열기도 동작하지 않습니다. 저장소가 연결된 Vercel 주소에서 시험합니다.

## 사용 기술

React · Vite · Tailwind CSS · [react-pageflip](https://github.com/Nodlik/react-pageflip)

## 로컬에서 실행

Node.js가 필요합니다.

```bash
npm install
npm run dev
```

개발 서버는 http://localhost:3000 에서 열립니다.

## 배포

`main` 브랜치에 push 하면 Vercel(프로젝트 `story-flipbook`)이 자동으로 배포합니다.
